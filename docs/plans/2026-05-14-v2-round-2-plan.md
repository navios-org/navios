**Goal:** Clear two trivial round-1 leftovers flagged in the final review.

**Step 1: Read the file**

Locate two spots:
1. The `as` cast on `opts.options.result` in the selector at the bottom (~line 235): `(opts.options as { result?: 'data' | 'envelope' }).result`. After round 1's Task 5 (`result` added to `BaseEndpointOptions`), the cast is unnecessary.
2. `shouldValidate` computed twice — once in `runEnvelope` (~line 138) and once in `runData` (~line 197). Same expression.

**Step 2: Remove the `as` cast**

`BaseEndpointOptions.result` is first-class now, so:

```ts
// Before
const resultMode =
  (opts.options as { result?: 'data' | 'envelope' }).result
  ?? opts.context.config.defaults?.result
  ?? 'data'

// After
const resultMode =
  opts.options.result
  ?? opts.context.config.defaults?.result
  ?? 'data'
```

**Step 3: Lift `shouldValidate` into the selector scope**

Move the `shouldValidate` computation from each composer up to the selector, then pass it down (or close over it). Cleanest:

```ts
export function createHandler<Options, TResponse>(opts: CreateHandlerOptions<Options>) {
  const resultMode = opts.options.result ?? opts.context.config.defaults?.result ?? 'data'
  const shouldValidate = opts.options.validateResponse !== false
  const endpoint = { method: opts.options.method, url: opts.options.url }

  const handler = async (request: HandlerRequest = {} as HandlerRequest): Promise<TResponse> => {
    return resultMode === 'envelope'
      ? runEnvelope<Options, TResponse>(opts, request, shouldValidate, endpoint)
      : runData<Options, TResponse>(opts, request, shouldValidate, endpoint)
  }

  handler.config = opts.options
  return handler
}
```

Update `runEnvelope` and `runData` signatures to accept the precomputed `shouldValidate` and `endpoint`. Remove their internal computations.

## Task 16: Update CHANGELOGs, READMEs, specs for round 2

**Step 1: Builder CHANGELOG additions**

Add to the 2.0.0 entry under "Changed":

```markdown
- **Socket and EventSource builders** now use the unified `onError(BuilderErrorEvent)` hook (matching the main builder). `onValidationError`, `onAckTimeout` (socket), and the separate `onError` (eventsource) are removed.
- **`RequestArgs<Url, QuerySchema, RequestSchema, UrlParamsSchema, IsServer>`** split into `ClientRequestArgs<Options>` (uses `z.input`) and `ServerRequestArgs<Options>` (uses `z.output`). The `IsServer` boolean generic is removed.
- **`BuilderErrorEvent.kind`** union extended with `'socket-ack-timeout'`, `'socket-transport'`, `'event-source-transport'`.
- **`BuilderErrorEvent`** gained optional `topic` (socket) and `eventName` (eventsource) fields.

### Removed (round 2)
- Socket `onValidationError`, `onAckTimeout` configs (use `onError`).
- EventSource `onError`, `onValidationError` configs (use unified `onError`).
- `RequestArgs<...IsServer>` boolean generic.
```

**Step 2: React-query CHANGELOG additions**

```markdown
### Removed (round 2)
- **`processResponse`** option on every helper (`client.query`, `client.mutation`, `client.infiniteQuery`, `client.multipart`, and their from-endpoint variants). Use TanStack's `select` option (passed to `use()` / `useSuspense()`) for projections, or transform in user code.
- **`client.queryFromEndpoint`, `client.mutationFromEndpoint`, `client.infiniteQueryFromEndpoint`** — folded into `client.query`, `client.mutation`, `client.infiniteQuery`. Each method now accepts either a config or an existing `EndpointHandler<Options>`.
- **`EndpointHelper`, `StreamHelper` types** — inlined at use sites.
- **`OptionsFromInline`, `BuildEndpointOptions` helpers** — no longer needed after `processResponse` removal.

### Migration

```diff
- const getUser = client.queryFromEndpoint(getUserEndpoint, {
-   processResponse: (data) => ({ ...data, displayName: `${data.name}` }),
- })
+ const getUser = client.query(getUserEndpoint)
+ // Then use TanStack's select:
+ const { data } = getUser.use({ urlParams: { id } }, {
+   select: (data) => ({ ...data, displayName: `${data.name}` }),
+ })
```

```diff
- const updateUser = client.mutation({
-   ..., processResponse: (data) => data.updated,
- })
+ const updateUser = client.mutation({ ... })
+ // Transform in onSuccess or in the caller
```
```

In `packages/builder/README.md`, no major changes; check the socket/eventsource sections for `onValidationError` examples and update.
